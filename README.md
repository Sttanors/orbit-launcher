# Orbit

Единый игровой лаунчер для Linux и Windows: локальная библиотека Steam и свои игры в полноэкранном интерфейсе с обложками. Не требует Steam Web API и ключей. Для запуска Steam-игр нужен вход в соответствующий аккаунт в клиенте Steam.

## Готовые пакеты

[GitHub Releases](https://github.com/Sttanors/orbit-launcher/releases): Windows 10/11 x64 — установщик `.exe`; Debian/Ubuntu — `.deb`; Fedora — `.rpm`; Arch — `.pkg.tar.zst`. Linux-сборки требуют glibc 2.35+ и устанавливаются в `/opt/orbit`. Пакет Arch устанавливается через `pacman -U`; это не публикация в AUR.

Windows-установщик устанавливает Orbit только для текущего пользователя, без прав администратора и без отдельной установки Python. EXE не подписан сертификатом издателя.

## Запуск из исходников

```bash
bash start.sh
```

На компьютере, где уже создан локальный ярлык `Orbit.desktop`, можно открывать его. Ярлык содержит абсолютный путь и не включён в репозиторий. Оконный режим: `bash start.sh --windowed`.

Требуется Python 3.10+ и PySide6 с QtWebEngine. Установка зависимостей:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python launcher.py
```

## Возможности

- Steam из обычной установки и Flatpak; несколько библиотек, локальные обложки, запуск через Steam с его настройками Proton.
- Установка определяется по манифесту Steam и наличию каталога. Зарегистрированные игры с отключённых дисков остаются в библиотеке с отметкой недоступности. «Открыть в Steam» передаёт управление клиенту; установка и обновления выполняются там.
- Свои игры: Linux — ELF, AppImage и исполняемые скрипты; Windows — `.exe` / `.com`; выбор файла и обложки, аргументы запуска, рабочая папка. Клавиша E открывает редактирование добавленной игры; идентификатор, избранное и история сохраняются. Нужны права на выполнение. Windows EXE требуют заранее настроенного скрипта Wine/Proton, который можно добавить как игру.
- Поиск, фильтры, сортировка, избранное, история запусков из Orbit. Удаление своей игры из списка сохраняет её файлы.
- Обычный запуск использует `steam -silent -applaunch APPID`, чтобы не вызывать главное окно Steam через URI. Orbit остаётся фоном до появления игры. Steam может показывать обязательные окна входа, обновления, установки или выбора варианта запуска. Успешная передача команды не гарантирует, что сама игра запустилась; сообщения Steam и игры остаются в их ведении.
- По умолчанию полный экран; интерфейс на русском.

## Два аккаунта Steam

Orbit читает сохранённые аккаунты из `config/loginusers.vdf`. Выбери Steam-игру → **E / Параметры** → укажи аккаунт с нужной лицензией → Сохранить. Можно выбрать «Текущий аккаунт Steam», чтобы не привязывать игру.

Первоначальная привязка берётся из LastOwner установочного манифеста, если этот аккаунт сохранён. Это последний известный владелец установки, а не проверка лицензии. Для игр второго аккаунта при необходимости поправь выбор вручную.

При запуске из другого аккаунта Orbit предлагает переключение. После подтверждения он отправляет Steam штатную команду `-shutdown`, ждёт завершения до 45 секунд без принудительного убийства процессов, затем выполняет `steam -silent -login ACCOUNT`. Игра запускается отдельной командой только после подтверждения входа именно в выбранный аккаунт по текущему сеансу Steam. На вход отводится 3 минуты, затем Orbit сообщает об ошибке и не запускает игру. Пока обнаружена запущенная игра Steam, переключение блокируется. На время переключения Orbit временно занимает полный экран поверх окон Steam. После подтверждённого входа главное окно Steam сворачивается через xdotool (X11 / Xwayland), а режим поверх остальных окон снимается до запуска игры. Системные окна входа доступны по F8: эта команда сразу снимает защитный экран. xdotool необязателен для запуска Orbit, но нужен для сворачивания главного окна Steam на X11 / Xwayland. Orbit не меняет файлы авторизации и не читает/хранит пароли; Steam использует свои сохранённые данные и при необходимости показывает вход / Steam Guard. Клиент может потребовать повторную авторизацию — полностью скрыть этот этап нельзя. Выбор аккаунта не даёт права запускать чужую лицензию.

Активный аккаунт определяется по работающему Steam и событиям входа из журнала текущего сеанса. Если определить его не удалось, Orbit предлагает явное переключение. Во время ожидания можно открыть Steam: F8 / X на геймпаде, или отменить отложенный запуск: Esc / B. Отмена не возвращает прежний аккаунт и не отменяет уже отправленную команду завершения Steam. При закрытии Orbit до окончания переключения отложенный запуск отменяется.

## Пропуск подготовки шейдеров Steam

Меню (F10) → «Пропуск подготовки шейдеров Steam» → «Перезапустить Steam и применить настройку».

Orbit запускает клиент с `STEAM_ENABLE_SHADER_CACHE_MANAGEMENT=0`. Это отключает систему предварительного кэширования Steam для всего сеанса клиента, а не нажимает кнопку «Пропустить» в окне. Для Flatpak переменная передаётся через `flatpak run --env=…`. Настройка сохраняется в Orbit и учитывается при смене аккаунтов. Если Steam уже работал, нужна его полная перезагрузка: переменные нового процесса не меняют существующий клиент. Запущенная игра блокирует перезапуск.

Возможны подёргивания при компиляции шейдеров во время игры. Собственная компиляция игры не отключается. Вернуть обычное поведение можно тем же переключателем и перезапуском Steam. Если запустить Steam вне Orbit, настройка Orbit не применяется автоматически. Для применения сохранённого режима при запуске лаунчера: `bash start.sh --apply-steam-settings`.

Документация Valve: [Steam client update — shader cache management](https://store.steampowered.com/news/posts/?enddate=1526517539&feed=steam_client).

## Данные и проверки

Свои игры, обложки, избранное и история сохраняются в пользовательской папке: Windows — `%LOCALAPPDATA%/Orbit`, Linux — `$XDG_DATA_HOME/orbit` (по умолчанию `~/.local/share/orbit`). Существующая `data/` рядом с исходниками продолжает использоваться; установленные пакеты всегда используют пользовательскую папку. Для другого места хранения задай `ORBIT_DATA_DIR`. Steam-файлы читаются, их содержимое не меняется. Поддерживается современный Steam appinfo v29; при другом формате названия берутся из установочных манифестов.

```bash
python3 -m unittest discover -s tests -v
node --check ui/app.js
python3 tests/switch_smoke.py
QT_QPA_PLATFORM=offscreen python3 tests/ui_smoke.py
```

Интерфейс — локальные HTML/CSS/JS в QtWebEngine; связь с Linux через QWebChannel. Отдельного веб-сервера нет.

## Сборка релиза

Версия задаётся в `launcher.py` (`VERSION`). Workflow **Build and release Orbit** запускается вручную в Actions или тегом `vVERSION`. Отдельные Linux- и Windows-задачи запускают тесты и собирают PyInstaller + QtWebEngine; Linux создаёт deb/rpm/Arch-пакет, Windows — установщик Inno Setup. Публикация происходит после обеих сборок и проверок запуска; вместе с пакетами прилагаются SHA-256 суммы. Релиз сначала создаётся черновиком и публикуется после загрузки файлов.

Для ручной сборки на целевой ОС: Python 3.12, `pip install -r requirements-build.txt`, затем `python build_release.py`. Linux также требует dpkg-deb, rpmbuild и zstd; Windows — Inno Setup 6. Qt и Python входят в пакеты. Личные данные и папки игр не копируются в сборку. Исходники проекта пока без открытой лицензии; метаданные зависимостей и их лицензии включаются в пакет.

## Orbit 0.2: загрузки, Proton, сохранения и консольный режим

Открой меню (F10 / Start) → **Возможности Orbit**.

### Торрент-загрузки

Вкладка **Загрузки** принимает magnet-ссылку или локальный `.torrent` и папку назначения. До двух загрузок идут одновременно, остальные ждут в очереди. Есть пауза, продолжение, ограничения загрузки и раздачи в КиБ/с (0 — без ограничения). Очередь восстанавливается после перезапуска; файлы проверяются повторно. Завершённые загрузки раздаются до паузы или удаления из очереди. Удаление записи сохраняет файлы. Кнопка добавления игры открывает обычную форму выбора исполняемого файла или установщика. Скачанные файлы не запускаются автоматически.

В исходной версии установи зависимости из `requirements.txt`; пакеты релиза уже содержат libtorrent и pygame-ce.

### Обновления

Вкладка **Обновления** проверяет последний стабильный релиз `Sttanors/orbit-launcher`. После проверки кнопка **Обновить и перезапустить** скачивает пакет для текущей ОС, проверяет SHA-256 из релиза и запускает установку. На Linux используется установленный пакетный менеджер через polkit (`pkexec`); системное подтверждение обязательно. Windows использует установщик Inno Setup. При отказе или ошибке установки снова запусти Orbit; скачанный пакет остаётся в пользовательской папке данных `updates`. Для непакетной установки на другой Linux-дистрибутив установи пакет вручную. Источник обновлений и список контрольных сумм находятся в том же GitHub-репозитории; отдельной криптографической подписи релизов пока нет.

### Proton

В форме добавления или параметров собственной игры выбери **Proton**, затем установленную версию. Orbit ищет Proton в библиотеках Steam и `compatibilitytools.d` (включая GE-Proton). Для каждой игры создаётся отдельная папка `prefixes/<id>` в данных Orbit. Можно указать `.exe`, аргументы и рабочую папку. Сам Proton и необходимые системные библиотеки устанавливаются отдельно; совместимость зависит от игры и версии Proton. На Windows игры запускаются напрямую.

### Облачные сохранения через папку

Выбери игру → **Сохранения**. Укажи папку сохранений, существующую папку облака / Syncthing и общий ключ игры (латиница, цифры, `-`, `_`). На втором компьютере путь к сохранениям может отличаться, а ключ должен совпадать. Сначала сохрани настройки, затем синхронизируй.

Orbit хранит ZIP-копии с контрольными суммами в `Orbit-Saves/<ключ>` внутри выбранной папки. Клиент облака переносит их между компьютерами. Orbit проверяет копию до запуска и синхронизирует после наблюдаемого завершения игры. Если обе стороны изменились или первое подключение содержит разные сохранения, автоматический запуск останавливается до ручного выбора версии. История позволяет восстановить старую копию. Перед восстановлением текущая папка копируется в локальный `save-backups`; дополнительные локальные файлы не удаляются. История и резервные копии не очищаются автоматически. Не выбирай папку с символическими ссылками, всей библиотекой игр или саму папку облака в качестве папки сохранений.

Облачный клиент должен успеть скачать версии перед запуском. Orbit не выполняет вход в облако и не хранит его пароль. Закрывай игру до ручного восстановления. Orbit должен оставаться запущенным до завершения игры; для сторонних загрузчиков, передающих запуск другому процессу, доступна ручная синхронизация.

### Консольный режим

Во вкладке **Консоль** можно включить возврат по Guide / PS и автозапуск после входа в систему. Полный экран включён по умолчанию. **Текущие игры** показывает игры, запущенные через Orbit, позволяет вернуться в окно или завершить процессы с подтверждением. Для сон / выключение также требуется подтверждение.

В текстовом поле нажми A / ×, чтобы открыть экранную клавиатуру: крестовина / стик выбирает клавишу, A вводит, B закрывает. Есть RU / EN, Shift, пробел и удаление. Для поиска клавиатура также доступна во вкладке **Консоль**.

Фоновый Guide / PS использует SDL и зависит от драйвера, сопоставления геймпада и перехвата кнопки Steam / рабочим столом. Возврат в окно игры на Linux работает через `xdotool` на X11 / Xwayland. На Wayland действуют ограничения композитора; используйте его переключение окон. Завершение игры посылает обычный запрос завершения только процессам наблюдаемой игры; не все игры обрабатывают его мгновенно.
